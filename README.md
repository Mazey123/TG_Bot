# 📈 Биржевой симулятор — Telegram-бот

Учебный проект по разработке интеллектуального бота с интеграцией внешних сервисов:
виртуальная биржа, портфель, PnL, уровни, достижения, квиз и ценовые алерты.

**Стек:** Python 3.11+ · aiogram 3 · SQLAlchemy 2 (async) · SQLite/aiosqlite · aiohttp · aiohttp-socks · pydantic-settings.

> Это симулятор. Он не подключается к брокеру и не является инвестиционной рекомендацией.

---

## 1. Что умеет бот

| Блок | Возможности |
|---|---|

| Торговля | Покупка/продажа с комиссией, FSM-сценарий «тикер → количество → подтверждение», проверка баланса и остатка позиции |
| Портфель | Средняя цена, текущая стоимость, нереализованный PnL, свободные средства, общий капитал |
| История | Последние сделки и последние квизы |
| Геймификация | XP и уровни, 7 достижений, ежедневный бонус, серия дней, таблица лидеров |
| Квиз | 3 категории × 6 вопросов, случайная выборка из 5, объяснение ответа, XP и бейдж за идеальный результат |
| Уведомления | `/alert AAPL 250` — фоновый worker проверяет цены и присылает сообщение; настройка уведомлений в `/settings` |
| Настройки | Включение/выключение уведомлений, безопасный сброс прогресса с подтверждением |
| Устойчивость | Повторы HTTP, таймауты, circuit breaker, TTL-кэш в памяти и SQLite, stale-cache, честно помеченные демо-данные |

## 2. Быстрый запуск

### Windows PowerShell

```powershell
cd "D:\Биржа Бот"
python -m venv venv
.\venv\Scripts\Activate.ps1
pip install -r requirements.txt
Copy-Item .env.example .env
# Откройте .env и вставьте TELEGRAM_TOKEN от @BotFather
python main.py
```

### Linux / macOS

```bash
python3 -m venv venv
source venv/bin/activate
pip install -r requirements.txt
cp .env.example .env
# заполните TELEGRAM_TOKEN
python main.py
```

База `data/stock_bot.db` создаётся автоматически при первом запуске. Каталог `data/`
уже есть в репозитории.

> Если в корне остался старый `stock_bot.db` от предыдущей версии, он не
> используется по умолчанию: новый бот работает с `data/stock_bot.db`.
> Если старая база всё же подключена через `DATABASE_URL`, при старте выполняется
> автоматическая миграция схемы: добавляются `daily_streak`, `last_bonus_at`,
> `transactions.side/fee/realized_pnl` и новые таблицы. Данные профиля и портфеля
> сохраняются. Перед миграцией боевой базы всё равно сделайте резервную копию.

### Проверка без интернета

В `.env`:

```env
MARKET_DATA_MODE=demo
```

Бот не будет обращаться к внешним API: все котировки и графики будут строиться на
детерминированных демо-данных с пометкой «Демо-данные». Это удобно для защиты лабы
в аудитории без стабильной сети. В режиме `auto` бот сначала пробует реальные API,
а при сбое переходит на кэш/демо и **явно пишет об этом пользователю**.

> Если токен когда-либо попадал в переписку или git, перевыпустите его в @BotFather.

### Если Telegram не подключается из РФ

Ошибка `Cannot connect to host api.telegram.org:443` означает, что Python-процесс
не может достучаться до Bot API. **MTProto-прокси, настроенный внутри Telegram
(`mtproto://`), здесь не поможет**: он проксирует MTProto-соединение клиента
Telegram, а бот ходит в Bot API по обычному HTTPS через `aiohttp`.

Варианты:

1. **Системный VPN.** Включите VPN на всём компьютере — `PROXY_URL` не нужен.
2. **Локальный SOCKS5/HTTP-прокси.** Если у вас v2rayN, Nekoray, Hiddify или
   другой клиент с локальным mixed-портом, укажите его в `.env`:

   ```env
   PROXY_URL=socks5://127.0.0.1:10808
   # или
   PROXY_URL=http://127.0.0.1:10809
   # с авторизацией:
   PROXY_URL=socks5://user:password@host:port
   ```

   Поддерживаются схемы `socks5://`, `socks4://`, `http://`. Строка `mtproto://`
   будет отклонена с понятной ошибкой.
3. **VPS вне РФ.** Самый надёжный вариант для постоянной работы: запустить бота
   на сервере, где `api.telegram.org` доступен напрямую.

Проверить прокси до Telegram можно так:

```powershell
curl.exe --proxy socks5h://127.0.0.1:10808 https://api.telegram.org
```

Если команда не отвечает — прокси не работает или порт указан неверно. При
старте бот сам делает `get_me()` и вместо длинного traceback печатает подсказку.

## 4. Архитектура

```
Telegram
   │
   ▼
middlewares/context.py  — антифлуд, сессия БД, профиль, внедрение сервисов
   │
   ▼
handlers/  — только приём событий, FSM, тексты и клавиатуры
   │
   ▼
services/  — бизнес-логика: торговля, портфель, квиз, алерты, рыночные данные
   │                    │
   ▼                    ▼
database/repo.py     providers + HTTP + cache
   │                    │
   ▼                    ▼
SQLAlchemy → SQLite  Yahoo / Stooq / CoinGecko / Frankfurter / QuickChart
```

### Структура каталогов

```
.

│   ├── migrations.py           # автоматическое обновление старой SQLite-схемы
│   ├── repo.py                 # репозитории, без SQL в хендлерах
│   └── session.py              # async engine, PRAGMA, init_db
├── handlers/
│   ├── start.py                # /start, /help, /bonus, меню
│   ├── market.py               # рынок, карточки, поиск, график
│   ├── trade.py                # FSM покупки/продажи
│   ├── portfolio.py            # портфель, история, профиль, топ
│   ├── quiz.py                 # FSM квиза
│   ├── alerts.py               # ценовые алерты
│   ├── settings.py             # настройки и сброс
│   └── errors.py               # глобальный error handler
├── services/
│   ├── assets.py               # справочник тикеров и алиасов
│   ├── cache.py                # TTL-кэш: память + SQLite
│   ├── http.py                 # aiohttp + retry + timeout
│   ├── market/                 # провайдеры и MarketService
│   ├── trading.py              # атомарные сделки, комиссия, PnL
│   ├── portfolio.py            # оценка портфеля
│   ├── gamification.py         # XP, уровни, бейджи, бонус
│   ├── quiz.py                 # банк вопросов
│   ├── chart.py                # график через QuickChart
│   └── alerts.py               # фоновый worker алертов
├── keyboards/inline.py         # все inline-клавиатуры
├── middlewares/context.py      # контекст запроса
├── utils/                      # форматирование, безопасность, логи
├── tests/                      # 28 unit-тестов (unittest)
├── data/                       # SQLite (создаётся автоматически)
├── .env.example
└── requirements.txt
```

Ключевое правило: **хендлеры не содержат SQL и не считают деньги вручную**. Вся
бизнес-логика — в сервисах, доступ к данным — в репозиториях, интерфейс — в
хендлерах и клавиатурах.

## 5. Внешние интеграции

| Сервис | Что даёт | Ключ | Роль |
|---|---|---|---|
| [Yahoo Finance Chart API](https://query1.finance.yahoo.com) | Котировки и история акций | не нужен | основной для акций |
| [Stooq CSV API](https://stooq.com/q/l/) | Резервные котировки акций | не нужен | fallback для акций |
| [CoinGecko API](https://www.coingecko.com/en/api) | Криптовалюты, 24h change, история | опционально `COINGECKO_API_KEY` | крипта |
| [Frankfurter API](https://www.frankfurter.app/) | Курсы валют (данные ЕЦБ) | не нужен | валютные пары |
| [QuickChart](https://quickchart.io/) | PNG-график по URL | не нужен | медиа-контент |

### Схема устойчивости

```
запрос → память (TTL) → SQLite-кэш (TTL) → внешний API
                                          ├─ retry (2 попытки, backoff)
                                          ├─ circuit breaker (90 сек)
                                          └─ stale-кэш (до 24 ч)
                                               └─ демо-данные (помечены)
```

* Все сетевые вызовы асинхронные, с `aiohttp.ClientTimeout`.
* При 429/5xx и сетевых ошибках выполняется повтор с задержкой.
* После серии ошибок провайдер временно отключается, чтобы не тормозить интерфейс.
* Устаревший кэш возвращается с пометкой `· кэш`, демо-данные — с `⚠️`.
* Торговля в симуляторе по резервной цене разрешена, но пользователь видит
  предупреждение.

### Кэш

| Данные | TTL |
|---|---|
| Котировки акций/крипты | 60 секунд |
| Валютные курсы | 1 час |
| История для графика | 30 минут |
| Резервные/демо-данные | 20 секунд |

Кэш хранится в таблице `api_cache` (JSON + `expires_at`) и дополнительно в
`MemoryTTLCache` процесса. Это снижает число обращений к API и ускоряет меню.

## 6. Модель данных

| Таблица | Назначение |
|---|---|
| `users` | Telegram ID, имя, баланс, XP, уровень, уведомления, серия бонусов |
| `portfolio` | Позиции: тикер, количество, средняя цена; уникальность `(user_id, ticker)` |
| `transactions` | История сделок: сторона, цена, комиссия, реализованный PnL |
| `badges` | Достижения; уникальность `(user_id, badge_code)` |
| `quiz_attempts` | История игр: категория, результат, XP |
| `price_alerts` | Порог, направление, флаг срабатывания |
| `api_cache` | Кэш ответов внешних API |
| `bot_meta` | Служебные отметки |

Деньги и количества — `Numeric`/`Decimal`, а не `float`. Покупка выполняется
условным `UPDATE users ... WHERE balance >= :cost`, поэтому баланс не может уйти
в минус. Для sell проверяется фактическое количество в позиции. Внутри процесса
сделки одного пользователя сериализуются `asyncio.Lock`.

## 7. FSM-сценарии

### Покупка/продажа

```
waiting_ticker → waiting_quantity → confirming → результат
```

* тикер можно выбрать кнопкой или ввести текстом;
* количество — кнопки 1/5/10, «Продать всё» или ручной ввод;
* перед выполнением показывается цена, сумма, комиссия и итоговый баланс;
* `/cancel` и кнопка «Отмена» очищают состояние.

### Квиз

```
выбор категории → вопрос → проверка ответа → следующий вопрос → результат
```

Правильный ответ выделяется, показывается объяснение; результат сохраняется в
`quiz_attempts`, начисляются XP и бейдж за 5/5.

Поиск по тикеру также использует отдельное FSM-состояние.

## 8. Геймификация

* Уровень: `level = floor(sqrt(xp / 100)) + 1`; прогресс-бар в профиле.
* XP: сделки (10–35 XP), бонус (+20), квиз (15 XP за ответ + 25 за идеальный).
* Достижения: первая сделка, первая прибыль, диверсификация, 10 сделок, «Кит»,
  идеальный квиз, серия бонусов 3 дня.
* Топ-10 — по XP, с местом текущего пользователя.
* Ежедневный бонус: +$250, кулдаун 24 ч, серия сохраняется при входе раз в 48 ч.

## 9. Безопасность и надёжность

* Токен и ключи — только в `.env`; в коде используется `SecretStr`.
* Валидация тикеров, количества, цены алерта; ограничение максимальной сделки.
* Только ORM/параметризованные запросы — SQL-инъекции невозможны.
* HTML-экранирование имён и внешних строк; фиксированный `parse_mode`.
* Антифлуд-middleware (30 событий / 10 секунд на пользователя).
* В логи пишется псевдоним `user_ref` (SHA-256), а не Telegram ID/имя.
* Фильтр логов вырезает токен и API-ключ.
* Глобальный error handler не показывает пользователю внутренние детали.
* `.gitignore` исключает `.env`, БД и логи.

## 11. Ограничения учебного проекта

* FSM хранится в `MemoryStorage`: после перезапуска незавершённый диалог
  сбрасывается (игровые данные в БД сохраняются). Для production нужен Redis.
* SQLite и один процесс polling — расчёт на учебную нагрузку. Для нескольких
  инстансов нужны PostgreSQL и распределённая блокировка.
* Yahoo Finance — неофициальный API; при блокировке включается Stooq/демо.
* Валютные пары (`USD/RUB`, `EUR/RUB`, `CNY/RUB`) доступны только как
  справочные котировки: в портфеле все торгуемые активы номинированы в USD.
* График строится внешним QuickChart; если картинка не отправилась, бот
  присылает текстовую сводку.
* Алерты проверяются фоновым worker'ом раз в 2 минуты; это не потоковый
  real-time-фид. Алерты не срабатывают по демо/устаревшим ценам, чтобы не
  присылать ложные уведомления.
* В режиме `MARKET_DATA_MODE=demo` ценовые алерты создаются, но не срабатывают:
  для них нужны реальные котировки.
